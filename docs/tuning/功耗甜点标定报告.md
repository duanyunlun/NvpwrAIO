## 3. 各变量的实际作用

### 3.1 最小电压（VMIN）—— 唯一的大杠杆 ★

**在 200W 档单独扫描 NVVDD/MSVDD 最小电压：**

```
VMIN 偏移   NVVDD下限   图形分数    GT1      GT2     相对变化
    0        625       27226     177.4    156.1      —
  -25        600       27178     177.8    155.3     -48    （噪声内）
 +100        725       27932     183.7    158.9    +706
 +200        825       28523     187.1    162.6   +1297   ★ 峰值
 +250        875       28187     184.5    161.0    -336   （回落）
 +300        925       FAILED      —        —      崩溃
```

**三个关键事实：**

1. **降低最小电压（负偏移）完全无效** —— 满载时 GPU 工作在电压曲线上端，
   下限根本不 binding。
2. **抬高最小电压效果显著** —— 200W 档单这一项就带来 +1297 分（+4.8%）。
   机制推测：抬高下限防止了满载时电压塌陷，让 GPU 能更稳地维持高频。
3. **存在最优值且与功耗正相关** —— 见下表。过高（+300@200W）会直接崩溃。

**最优 VMIN 随功耗的迁移规律：**

```
功耗     200W   225W   250W   275W   300W+
最优VMIN  +200   +250   +300   +350   +350（工具上限）
```

**约每 +25W 功耗对应 +50mV 最小电压偏移。**

**⚠️ 工具的钳制上限是 +350 mV**（请求 +400 会被静默压回 +350），
所以 275W 以上电压杠杆已经用尽。

### 3.2 显存频率 —— 完全无效

**在 275W 档固定其它变量只改显存偏移：**

```
显存偏移    图形分数    GT1      GT2
 +1000      31317     211.1    176.1
 +1500      31523     210.1    177.3
 +2500      31255     209.8    174.7
```

**三者完全在噪声范围内。Time Spy 的图形测试是核心受限的，显存带宽不是瓶颈。
显存偏移保持在 +1000 即可，更高的偏移只增加不稳定风险而无收益。**

### 3.3 XBAR 频率 —— 边缘

```
XBAR偏移    图形分数    GT1      GT2
 +200       31317     211.1    176.1
 +400       31466     214.4    173.8
```

**总分在噪声内，但 GT1 稳定高约 3 帧而 GT2 略降。可以认为 XBAR +200 已经足够。**

### 3.4 核心频率偏移 —— +400 会崩

```
core +200   31317     正常
core +400   FAILED    127 秒崩溃
```

**在电压下限已抬到 975mV 的前提下，核心目标 +400 超出了供电能力，直接崩溃。
+200 是安全值。**

## 4. 过程中踩到的工程坑

### 4.1 NvpwrCtl 的 CLI 把 5090 写死在 225W

`cli/nvpwrctl.cpp` 里有一张硬编码表：

```cpp
else if (profile == NvpwrProfileRtx5080Laptop || profile == NvpwrProfileRtx5090Laptop)
    valid = valid && watts >= 175 && watts <= 225 && (watts % 5) == 0;
```

**所以 `NvpwrCtl set 5090 250` 会被拒绝，静默停在 225W。**
（第 11 轮就是这么被骗的 —— 标称 250W 实际跑在 225W。）

**驱动本身的上限是 `POWER_CEILING_DEV = 350000`（350W），图形界面能设到 350W
是因为它直接发 IOCTL，绕过了 CLI 的表。**

**解决办法**：`tools/tune/Set-Power.ps1` 直连 `\\.\Nvpwr` 发
`IOCTL_NVPWR_SET_POWER`，结构里的 `MaxMilliwatts` 字段（1.9.0 新增）就是会话上限。

### 4.2 高功耗下 IOCTL 可能失败并触发驱动回滚

**第 16 轮**请求 300W 时 IOCTL 返回 `Win32=31 (ERROR_GEN_FAILURE)`，
驱动随即回滚到 `STOCK_BASELINE`：

```
State: STOCK_BASELINE (9)
Flags init/elig/amt: 1 / 0 / 0     ← eligibility 和 amount 被清
UPPER: 175000                       ← 功耗墙回到出厂值
```

**那一轮实际跑在 175W，分数只有 18946（对比正常的 31700）。**
重新下发一次 275W 即可恢复 `APPLIED`，之后 300W 也能设上。

**这个坑不会报错，只会让分数莫名其妙地暴跌 —— 所以每轮之前必须校验驱动状态。**

### 4.3 3DMark 的自动化要点

- **坐标要 ×2**：3DMark 是 DPI-unaware，UIA 报的是逻辑坐标，实际点击需要 2 倍。
- **按钮不是 UIA Button**：CEF 自绘，只能用文字定位 + 鼠标坐标点击。
- **「再次运行」和「在线比较结果」只差 80 像素**：点错会打开浏览器并弹出
  Futuremark 账户对话框，挡住一切。
- **结果页布局会变**：「再次运行」的 Y 坐标在 1616~1654 之间浮动，必须每次用 UIA 重新定位。
- **CEF 虚拟列表**：滚动后未渲染的项不会出现在 UIA 树里，只能按截图像素点。
- **Steam 卡 `Running=1`**：强杀 3DMark 后 Steam 会一直报 `AppError_16 / WaitingPrevProcess`，
  改注册表也没用，必须重启 Steam（会登出，需要点头像登录）。

## 5. 复现方法

```powershell
# 设功耗（绕开 CLI 的 225W 限制）
tools\tune\Set-Power.ps1 -Watts 275

# 设频率与电压（最大电压恒为 0 = 不动）
mvolt+.exe --core 200 --mem 1000 --xbar-offset 200 `
           --nvvdd-offsets "350,0,0,0" --msvdd-offsets "350,0,0,0"

# 每轮跑测试
tools\tune\Run-One.ps1 -PowerW 275 -CoreMhz 200 -MemMhz 1000 -XbarMhz 200 `
                       -NvvddVmin 350 -MsvddVmin 350 -Note "275W vmin+350"

# 结果落在 dist\tuning\timespy-sweep.csv
```

**`--nvvdd-offsets` / `--msvdd-offsets` 的四个字段是 VMIN,REL,ALT,OV。
后三个恒为 0 —— 即最大电压永远不动。**
